# Формат каталога sdd/ и требований

Это канон файловой конвенции SDD-процесса (Spec-Driven Development). На него ссылаются скиллы
`sdd-design`, `sdd-tasks`, `sdd-apply`, `sdd-archive` — при изменении структуры здесь нужно синхронно
поправить упоминания в них.

## Структура каталога

```text
sdd/
├── specs/<capability>/spec.md          # актуальные требования — источник правды
└── changes/
    ├── <change-id>/                    # активное изменение, kebab-case, напр. add-user-export
    │   ├── proposal.md                 # Зачем / Что меняется / Влияние
    │   ├── design.md                   # опционально — создаёт sdd-design
    │   ├── tasks.md                    # чеклист — создаёт sdd-tasks
    │   └── specs/<capability>/spec.md  # дельты требований
    └── archive/                        # завершённые изменения — переносит sdd-archive
```

`sdd/specs/<capability>/spec.md` меняется только при архивации изменения (`sdd-archive`). Пока
изменение активно, требования живут как дельты в `sdd/changes/<change-id>/specs/`.

## Формат требования

И в `sdd/specs/`, и в дельтах требование оформляется одинаково:

```markdown
### Requirement: <краткое название>
Система ДОЛЖНА <проверяемое утверждение>.

#### Scenario: <название сценария>
- **WHEN** <условие/действие>
- **THEN** <ожидаемый результат>
```

У каждого требования — минимум один `Scenario`. Формулировка требования должна быть проверяемой:
«Система ДОЛЖНА» + конкретное поведение, а не намерение или пожелание.

## Формат дельта-файла

Дельта-файл (`sdd/changes/<change-id>/specs/<capability>/spec.md`) группирует требования под тремя
возможными заголовками:

```markdown
## ADDED Requirements

### Requirement: <название нового требования>
Система ДОЛЖНА ...

#### Scenario: ...
- **WHEN** ...
- **THEN** ...

## MODIFIED Requirements

### Requirement: <название существующего требования>
<полный новый текст требования — не диф, а целиком>

#### Scenario: ...
- **WHEN** ...
- **THEN** ...

## REMOVED Requirements

### Requirement: <название удаляемого требования>
Причина удаления: <почему требование больше не нужно>
```

- `ADDED` — новое требование, которого не было в `sdd/specs/`.
- `MODIFIED` — приводится **полный** новый текст требования целиком, не только изменившаяся часть.
- `REMOVED` — только заголовок требования и причина удаления, без текста самого требования.

Дельта-файл может содержать любую комбинацию из трёх секций — используются только нужные.
